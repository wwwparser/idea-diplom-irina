# Диплом: отказоустойчивая инфраструктура сайта в Yandex Cloud

Полный учебный стенд развёрнут в облаке `cloud-limellis`, каталог `diplom-irina`. Шесть отдельных непрерываемых ВМ, Application Load Balancer, нативные Zabbix/PostgreSQL, Elasticsearch, Kibana и Filebeat. Инфраструктура — Terraform; конфигурация — Ansible. Исходное задание: [IDEA.md](IDEA.md).

Пароль передаётся руководителю отдельно и отсутствует в репозитории. Для учебных HTTPS-интерфейсов без домена выпущены самоподписанные сертификаты на 90 дней. Браузер покажет предупреждение до явного доверия сертификату; публичные сертификаты и их проверенные SHA-256 — в [инструкции доступа](docs/ACCESS.md). SSH доступен только с разрешённого административного адреса, через отдельный бастион. Elasticsearch не имеет публичного IP. Адреса актуальны на 24 октября 2026 года; остановка/запуск может изменить динамические IP.

## Что проверено

- Оба приватных nginx находятся в разных зонах d/e, используют один образ Ubuntu 22.04 и одинаковый SHA-256 сайта.
- ALB возвращает HTTP 200 от обоих backend. При остановке nginx на web-a получены 20 из 20 ответов 200 от web-b; после запуска web-a восстановлена балансировка.
- Zabbix получает данные всех шести ВМ. Настроены 176 дополнительных USE items, 80 графиков с пороговыми линиями, шесть страниц dashboard и триггеры.
- Filebeat доставляет access.log и error.log обоих nginx; Elasticsearch имеет статус green, Kibana показывает реальные события.
- Snapshot schedule подключён ко всем шести boot disks: ежедневно в 09:06 UTC / 12:06 МСК, хранение 168 часов. Первые шесть плановых снимков имеют статус READY.
- Дамп PostgreSQL восстановлен в отдельную тестовую БД с проверкой всех шести узлов. Файл сайта восстановлен из планового снимка диска в другой зоне, SHA-256 совпал; временные ресурсы удалены.
- Повторный Ansible: `changed=0`, `failed=0`, `unreachable=0` на всех ВМ. Финальный Terraform plan: `No changes`.

Матрица требований и реальные протоколы — [ACCEPTANCE.md](docs/ACCEPTANCE.md). Объяснение архитектуры, безопасности, мониторинга и компромиссов — [DIPLOMA.md](docs/DIPLOMA.md). Команды развёртывания и эксплуатации — [RUNBOOK.md](docs/RUNBOOK.md).

## Структура

```text
terraform/       полная схема: 6 ВМ, подсети, SG, NAT, ALB, snapshot schedule
ansible/         нативные роли, host firewall, TLS proxy, systemd metrics collector
scripts/         inventory, bootstrap API, мониторинг, проверки отказа/восстановления
site/            одинаковый статический сайт для двух nginx
docs/            отчёт, доступ, runbook и матрица приёмки
evidence/        результаты API/команд, экспорты и скриншоты
terraform-debug/ исторический двухмашинный профиль; сейчас удалён
```

## Особенности реализации

Использована существующая VPC через read-only data source; подсети и сервисные ресурсы диплома отдельные. Старый стенд и его копии не изменялись. Квоту снимков увеличили до 96. Шесть ВМ по 2 vCPU с гарантированной долей 20% занимают по 1,2 CPU квоты в каждой зоне; увеличение CPU не потребовалось. SSD/HDD распределены в пределах существующих дисковых квот.

Общая SG для двух UI дополнительно ограничена UFW на каждом сервере. Публичный HTTPS защищает пароли; исходные UI-порты разрешены только административному /32. Elastic-пакеты версии 8.19.23 устанавливаются из зеркала Yandex с проверкой подписи исходным ключом Elastic; Docker не используется.

Отказоустойчив веб-уровень. Zabbix, Elasticsearch и Kibana представлены одним экземпляром каждый. Снимки работающих дисков crash-consistent; для PostgreSQL дополнительно применяется `pg_dump`. Это учебная инфраструктура с минимальными ресурсами, без заявления о промышленном SLA. После проверки руководителем стенд нужно остановить или удалить собственные ресурсы, чтобы прекратить дальнейшие расходы согласно выбранному варианту.

IAM-токены, ключи SSH, пароли, Vault secrets, state, tfvars и планы исключены из Git. Секреты не хранятся в истории репозитория.
